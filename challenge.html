01

Challenge Overview

The G2A Jenga Challenge evaluates world models, action-conditioned world models, world action models, and robot policies in manipulation settings where understanding the physical consequences of an action is critical to success.

Tower manipulation provides a compact but challenging testbed for spatial reasoning, physical forecasting, contact-aware interaction, and long-horizon control. Before executing an action, a capable system should reason about the current structure, anticipate possible outcomes, and select actions that accomplish the task without destabilizing the environment.

The challenge therefore goes beyond visual prediction alone. It asks whether predicted or modeled future outcomes can support executable, reliable, and physically consistent robot behavior.

Central Question

Can a model forecast the physical consequences of different robot actions before execution, and use those forecasts to choose actions that successfully manipulate a structured and fragile environment?

Core Capability

Spatial Understanding → Action Rollout → Physical Forecasting → Action Selection → Execution

02

TOWER Benchmark

The G2A Jenga Challenge is powered by TOWER, a reproducible robotics simulation benchmark for long-horizon tower manipulation.

TOWER provides calibrated, versioned task environments and a model-agnostic evaluation interface for standardized policy evaluation. The primary physics-based benchmark runtime uses Isaac Sim on NVIDIA GPUs, while participant policies can run either directly inside the evaluation process or through the tower-policy-v1 HTTP/WebSocket adapter protocol.

Runtime

Isaac Sim Benchmark

Official physics-based benchmark evaluation runs in Isaac Sim using standardized task definitions, versioned scenes, and reproducible configurations.

Isaac Sim · NVIDIA GPU · Physics-based evaluation
Interface

Model-Agnostic Evaluation

Policies can run in-process or connect through the tower-policy-v1 HTTP/WebSocket adapter protocol, supporting local PyTorch, JAX, and remote policy implementations.

In-process · HTTP · WebSocket
Reproducibility

Versioned Tasks & Assets

Benchmark Tasks

TOWER provides versioned tower-manipulation task families for evaluating long-horizon robot policies under standardized physical conditions.

Task Family

tower_transfer

Tower-transfer tasks evaluate structured long-horizon manipulation across source and target tower configurations.

Long-horizon manipulation · Spatial correspondence
Task Family

cross_tower_transfer

Cross-tower transfer configurations evaluate sequential manipulation while requiring policies to preserve the intended tower structure throughout execution.

Sequential manipulation · Structure preservation
Task Family

aligned_stack

The aligned_stack family is part of the official TOWER task catalog. Task layouts and per-block geometry and physics specifications are versioned together with the benchmark configuration.

Versioned layout · Standardized physics contract

Versioned Task Definitions

TOWER task layouts and block variants are versioned independently of the evaluator. The official catalog uses task identifiers including tower_transfer_X, cross_tower_transfer_X, and aligned_stack_X.

05

Evaluation

Policies are evaluated using the official TOWER benchmark runtime and standardized challenge metrics.

Metric Description Direction
Success Rate Fraction of evaluation episodes in which the complete task is successfully finished. ↑
Level Progress Rate Fraction of required task progress successfully completed before termination. ↑
Collapse Rate Fraction of episodes in which the tower structure collapses during execution. ↓
Completion Time Time required from task initialization until successful completion or termination. ↓
Leaderboard Ranking

Success Rate will be used as the primary metric in the initial challenge release. Progress, collapse, and completion time will be reported as complementary metrics. Final ranking and tie-breaking rules will be published with the official evaluation release.

06

Data & Participation

TOWER provides the evaluator, policy integration interface, reproducibility tools, and benchmark configuration needed to develop and validate participant policies.

Current TOWER Capabilities

  • Isaac Sim / GPU benchmark runtime. The primary physics-based evaluation runtime uses Isaac Sim and is installed separately from the Python workspace.
  • Policy adapter interface. Participant policies can connect through the provided HTTP/WebSocket adapter template using the tower-policy-v1 protocol.
  • CPU smoke test and integration harness. A deterministic CPU reference backend is provided for installation checks, continuous integration, configuration validation, and policy integration.
  • Task and asset validation. The evaluator supports validation of task descriptors and benchmark asset closure.
  • Versioned task definitions. Task layouts and block variants are versioned independently from the evaluator.
Important

The deterministic CPU backend is an integration and testing harness. It does not simulate tower contacts and is not the official physics-based benchmark. Official physical interaction evaluation requires the Isaac Sim runtime.

Quickstart

CPU Installation Check

Clone the repository, install the locked workspace dependencies, and run the TOWER smoke tests before configuring the Isaac Sim benchmark runtime. 

git clone https://github.com/tower-benchmark/TOWER.git
cd TOWER
uv sync --locked
uv run --package tower-eval tower smoke
uv run --package tower-eval pytest

Policy Integration

Participants may wrap their own PyTorch, JAX, or remote policy using the provided three-method PolicyAdapter interface. The same policy lifecycle is used for local and remote evaluation.

07

Phase 2: Sim-to-Real Evaluation

Phase 2 extends the challenge from standardized simulation evaluation to comparison across simulated and physical robot environments.

The goal is to study not only whether a policy succeeds in simulation, but also how reliably simulation performance predicts behavior on the corresponding physical robot system.

Simulation

Standardized Evaluation

Policies are first evaluated under controlled simulation conditions using standardized task configurations and benchmark metrics.

Real

Physical Evaluation

Selected policies are evaluated on the corresponding physical robot setup using matched manipulation tasks.

Analysis

Sim-to-Real Consistency

Simulation and real-world results are compared to analyze how well benchmark performance transfers to physical execution.

Phase 2 Details
